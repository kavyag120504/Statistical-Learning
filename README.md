# UniDL4BioPep — Peptide Bioactivity Classification + Sliding-Window Masking

**Course:** DSC4804 Statistical Learning · **Group 18**
**Base paper:** UniDL4BioPep (Du et al., 2023) — frozen **ESM-2** (`esm2_t6_8M_UR50D`,
320-dim embedding) + a small **1-D CNN**.

This project (1) predicts whether a peptide is **active** (binary) from its amino-acid
sequence, (2) compares the CNN against classical models on identical inputs, (3) tests how
far the 320-D embedding can be **PCA-compressed**, and (4) uses a **sliding-window masking**
technique to show *which regions* of each peptide the model depends on — and checks that the
result is stable and better than random.

> Important wording: regions found by masking are called **model-dependent** /
> **model-associated**, **not** causal. Nothing here is lab-validated.

---

## The four questions

1. Does a CNN on ESM-2 embeddings predict activity well?
2. Does the CNN beat simpler models (Logistic Regression, SVM, Random Forest, XGBoost)?
3. How much can the embedding be PCA-compressed (90 / 95 / 99 % variance) before it hurts?
4. Which peptide regions are most impactful, and is that stable and better than random?

The plain-language answers, built **only from numbers the code actually produced**, are in
**[`results/summary.md`](results/summary.md)** (auto-generated by `src/make_summary.py`).

## Datasets (4 tasks, kept SEPARATE — never merged)

From the public UniDL4BioPep repo (https://github.com/dzjxzyd/UniDL4BioPep). Each is a
distinct binary task; `label == 1` means **active / positive** in every file (verified and
printed per dataset in `src/split.py`). The two small sets (**toxicity, acp**) were used to
debug the pipeline first, as the brief asks.

| dataset       | task                  | train | test | test pos % | PCA 90/95/99 comps |
|---------------|-----------------------|------:|-----:|-----------:|--------------------|
| toxicity      | Toxicity (2021)       | 3284  | 580  | 46.4       | 30 / 54 / 151      |
| acp           | Anticancer (ACP main) | 1378  | 328  | 49.4       | 24 / 43 / 125      |
| neuropeptide  | NeuroPred             | 3880  | 969  | 50.1       | 34 / 62 / 167      |
| ace           | ACE-inhibitory        | 1826  | 526  | 26.6       | 30 / 56 / 155      |

(The brief also lists Antimicrobial and Bitter; four datasets were agreed as sufficient.
`ace`'s test set is imbalanced — class weights are used everywhere.)

### Label orientation (the brief warns the repo README is contradictory)
We checked each file and **use `label == 1` = active consistently**. Three sets are balanced
50/50 by construction; `toxicity` and `ace` are printed with their exact pos/neg counts in
the `split` stage so the choice is explicit and reproducible.

### Cleaning (counts printed at every stage)
`prepare_dataset.py` assembles the raw `.xlsx`; `preprocess_dataset.py` cleans: strip/upper,
drop non-standard residues (keep only the 20 standard AAs), coerce labels to 0/1, drop
label-conflicting sequences, de-duplicate, and keep the TRAIN copy when a sequence appears in
both splits. Result: **0 duplicates, 0 non-standard residues, 0 exact train/test overlap.**

## Leakage control (`src/split.py`)

- The repo gives official **train/test** files — we use them (comparable to the paper).
- **Near-identical** train↔test check: for each test peptide we take the best **3-mer Jaccard**
  similarity to the train set (length-bucketed for speed) and drop any test peptide ≥ 0.90.
  Removed: **toxicity 0, acp 16, neuropeptide 1, ace 0** (see `results/split_summary.csv`).
- A **15 % validation** set is carved from **TRAIN only**, stratified, and **re-drawn per seed**
  (`make_train_val`) so the 5 seeds give real variance.
- **Everything that learns** (min-max scaler, PCA, models, CNN early stopping) is fit on
  **TRAIN only**. Validation tunes; **test is touched once**, at metric time.

## Pipeline

```
raw .xlsx ─ prepare_dataset.py ─► data/processed/   (assemble)
          ─ preprocess_dataset.py ─► data/clean/     (clean, per dataset)
src/split.py        near-dup removal + split files      ─► data/splits/, results/split_summary.csv
src/embed.py        frozen ESM-2, mean-pool (320-d), cached ─► data/embeddings/*.npz
src/pca_ablation.py min-max + PCA 90/95/99 (TRAIN only)  ─► results/pca_components.csv
src/models.py       CNN + LR/SVM/RF/XGB, 5 seeds × 4 reprs ─► results/predictions/*.npz
src/metrics.py      8 metrics, mean±std, bootstrap MCC CI  ─► results/summary_<ds>.csv
src/masking.py      sliding-window importance (X + delete) ─► results/masking/*.pkl
src/validate.py     deletion test, stability, composition, position ─► results/*.csv
src/optimise.py     (optional) guided mutation + RF recheck ─► results/optimise_<ds>.csv
src/figures.py      all plots (PDF + PNG, B/W, blue borders) ─► figures/
src/make_summary.py the four questions answered in words    ─► results/summary.md
```

**Run everything:** `python run_all.py` (CPU is fine — see below). Or one stage at a time,
e.g. `python -m src.models toxicity`. Every stage is **cached** (re-runs skip finished work).

### Embeddings
`facebook/esm2_t6_8M_UR50D`, **frozen** (no fine-tuning), via HuggingFace `transformers`.
Final-layer residue vectors are **mean-pooled excluding the `<cls>`/`<eos>` special tokens**
and padding → one **320-d** vector per peptide (shape asserted). Batched, `torch.no_grad()`,
cached to `data/embeddings/`. GPU is used automatically if present; it is not required.

### Models
- **CNN (UniDL4BioPep replica):** treat the 320-vector as a length-320, 1-channel signal →
  `Conv1d(1→32, k=3, stride=1, ReLU)` → `MaxPool` → `BatchNorm` → `Dropout(0.15)` → Flatten →
  `Dense(64, ReLU)` → `Dropout` → `Linear(2)` softmax. **SGD**, step-decay LR, **early stopping**
  on validation accuracy (keep-best weights), max 200 epochs. Class weights for imbalance.
- **LR / SVM(RBF) / RandomForest / XGBoost:** small **cross-validated** hyper-parameter grids on
  TRAIN only; `class_weight="balanced"` / `scale_pos_weight` for imbalance.
- **5 seeds**, report **mean ± std**.

### Metrics
Accuracy, Balanced Accuracy, Sensitivity, Specificity, F1, **MCC (main)**, ROC-AUC, PR-AUC,
at threshold 0.5, plus a **95 % bootstrap CI for MCC** on the test set. One table per dataset:
`results/summary_<dataset>.csv` (rows = model × representation).

### Masking (the main part — `src/masking.py`)
`predict(seq)` = ESM-2 embed → TRAIN min-max scaler → the canonical full-320 CNN. For each
correctly-predicted **active** test peptide: slide a window `k ∈ {3,5,7,9}` (stride 1), replace
the window **in the sequence** (not the embedding), re-embed, predict, and record
`Δp = p_full − p_masked`. Two styles — **`X`** (unknown-residue token) and **`delete`** — so the
result doesn't hinge on one trick. **Residue importance** = mean Δp of windows covering that
residue. All masked variants of a peptide are embedded in **one batched call**, under
`no_grad`, with an in-memory cache. Peptides shorter than `k` are handled (skip that `k`).

### Validating the masking (`src/validate.py`)
- **(a) Deletion test:** mask the top-m vs random-m vs bottom-m windows; paired **Wilcoxon**
  (top vs random) + rank-biserial effect size.
- **(b) Stability:** **Spearman** of residue-importance profiles across `k`, across styles,
  (and across seeds via the canonical-CNN seed).
- **(c) Composition:** amino-acid log2-enrichment in top windows vs the rest (e.g. K, R, L, W, C).
- **(d) Position:** mean importance by **relative position** (N→C, 10 bins), over active peptides.

## Compute environment & the CPU-vs-GPU decision

Measured on the development laptop: Python 3.13, **PyTorch CPU-only**, 12 cores. ESM-2 8M runs
at **~6 ms/sequence** (batch 32) on CPU, so **the whole project runs on a laptop** — one-time
embedding of all ~12.8k sequences is ~2–4 min; the masking stage is the slow part (~1–2 h total,
fully cached). A GPU (e.g. Kaggle/Colab) only speeds this up; it is **not required**. The code
auto-selects GPU when available. Library versions are logged to `results/versions.json`;
`requirements.txt` pins them.

## For a teammate cloning this repo (no retraining needed)

Everything required to **run the demo** is committed — all trained models and the cached
embeddings — so you do **not** retrain or rerun any pipeline stage. One-time setup:

```bash
git clone <repo-url> && cd statistical_learning
python -m venv .venv && .venv\Scripts\activate      # (Windows; use source .venv/bin/activate on mac/linux)
pip install -r requirements.txt                     # pinned versions — needed so the saved models load
python -m src.setup_check                            # verifies files + downloads ESM-2 once + test-predicts
streamlit run app.py                                 # launch the demo
```

Two things to know:
- **Internet is needed on the FIRST run only.** The demo re-embeds the peptide you type, and the
  ESM-2 weights (~30 MB, `facebook/esm2_t6_8M_UR50D`) download from HuggingFace the first time, then
  cache offline. `src/setup_check.py` triggers this download up front — run it once with internet.
- **Use the pinned versions** in `requirements.txt` (ideally a fresh venv). The saved models are
  pickled, so a very different scikit-learn/xgboost/numpy could fail to load them.

What is committed vs. not: committed = `models_saved/*.joblib` (classical), `results/masking_models/*.pt`
(CNN), `data/embeddings/*.npz` (cached vectors), plus all `results/` tables and `figures/`. Not
committed = ESM-2 weights (download once, above) and `__pycache__`/logs (see `.gitignore`).

## Live demo / interface

The trained models are saved to disk so a brand-new peptide can be scored **without any
retraining** (important for a live demo — ESM-2 embeds each sequence in milliseconds on CPU).

```bash
python -m src.save_models        # one-time: persist seed-0 full-320 models
                                 #   -> models_saved/<dataset>__<model>.joblib  (logreg/svm/rf/xgb)
                                 #   -> results/masking_models/<dataset>_cnn.pt  (CNN, from masking)

streamlit run app.py             # GUI: pick task + model, type a peptide, get P(active);
                                 #      the CNN also shows live residue-importance (why)
```

No-GUI fallback (works even if Streamlit is unavailable on the exam machine):

```bash
python -m src.predict -d toxicity -m cnn --seq CCDWDWCDHICTCCGG --explain
python -m src.predict -d acp      -m all --seq FAKKLAKKAKLAKKL        # compare all 5 models
```

Demo-ready **active** example peptides (predicted active, p≈1.0): toxicity `CCDWDWCDHICTCCGG`,
acp `FAKKLAKKAKLAKKL`, neuropeptide `QEADPSSSLEADSTLKDEPRELSNM`, ace `HKEMPFPKYPVQPF`.

The saved models are the **same** seed-0 classifiers behind the benchmark table: live predictions
reproduce the cached test predictions to ~1e-6 (verified in-code). `src/inference.py` is the single
code path shared by the app and the CLI (embed → scale with the train scaler → predict).

## Limitations
- The **`X` (unknown-residue) mask is an unusual input for ESM-2**; the model may partly react
  to the mask token itself, not only to the hidden biology. The `delete` style is included as a
  cross-check.
- Results are **specific to these four datasets** and the paper's train/test split.
- Important regions are **model-dependent / model-associated**, not shown to **cause** activity.
- The optional optimisation shows only **what the model prefers** (re-checked with a second
  model, Random Forest); it is **not** evidence of real potency. **None of this is lab-validated.**
